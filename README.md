# Pulse — Go + HTML, Windows

Клиент-серверный стартовый проект: вход, серверная SQLite, резервные копии, установщик и обновления. Прикладные разделы (товары, документы и т. п.) пока не реализованы.

## Установка
В GitHub → Actions → Test and build Windows installer скачайте артефакт `windows-installer`, распакуйте и запустите `setup.exe` (Windows x64). Клиент открывает HTML-интерфейс в браузере по умолчанию через локальный Go-сервер; это не встроенный WebView. Установка без прав администратора. Сервер входит в комплект, но запускается отдельно; служба Windows автоматически не создаётся.

## Сервер (PowerShell)
```powershell
$env:ADMIN_LOGIN = 'admin'
$env:ADMIN_PASSWORD = 'replace-with-a-long-unique-password'
$env:DATA_DIR = "$env:LOCALAPPDATA\PulseServer\data"
$env:BACKUP_INTERVAL = '24h'
& "$env:LOCALAPPDATA\Programs\Pulse\pulse-server.exe"
```
Первый запуск создаёт администратора. Дальнейшие изменения ADMIN_PASSWORD не меняют уже сохранённый пароль. Пароли — bcrypt; случайные токены хранятся в БД как SHA-256, действуют 8 часов, при выходе удаляются. Регистрация пользователей через UI пока отсутствует.

По умолчанию сервер слушает `127.0.0.1:8080`. Для сети задайте `LISTEN_ADDR=0.0.0.0:8443`, `TLS_CERT` и `TLS_KEY` (PEM) и настройте firewall. Без TLS используйте только loopback либо HTTPS reverse proxy. Не публикуйте незащищённый HTTP в сеть.

## Клиент
```powershell
$env:SERVER_URL = 'https://your-server.example:8443'
& "$env:LOCALAPPDATA\Programs\Pulse\pulse-client.exe"
```
По умолчанию подключение к `http://127.0.0.1:8080`. Для удалённых серверов обязателен HTTPS с доверенным сертификатом. Клиент не обращается к SQLite напрямую, только к API. Токен хранится в памяти страницы, не в localStorage.

## Резервное копирование
Согласованный снимок SQLite через `VACUUM INTO` при запуске и далее каждые `BACKUP_INTERVAL` (Go duration: `1h`, `24h`, минимум `1m`). Каталог `BACKUP_DIR`, по умолчанию `DATA_DIR/backups`. Ошибки выводятся в журнал сервера. Старые копии автоматически не удаляются: настройте внешний retention и копирование на другой диск. Файлы содержат чувствительные данные — ограничьте Windows ACL и используйте шифрование диска.

Восстановление: остановите сервер, сохраните текущие `app.db`, `app.db-wal`, `app.db-shm` в другой каталог, уберите эти три файла из DATA_DIR, скопируйте выбранный backup как `app.db`, запустите сервер. В копиях есть сеансы: для принудительного выхода всех пользователей очистите таблицу `sessions` после восстановления.

## CI и новые версии
Каждый push, PR и ручной запуск собирает и тестирует проект, затем создаёт `setup.exe` через Inno Setup. Артефакты доступны в Actions; это не публичный релиз.

Публикация: создайте GitHub Release с тегом вида `v1.0.0` на проверенном коммите текущей ветки, либо отправьте такой тег с машины сопровождающего. Push тега запускает workflow, который создаёт Release с установщиком и SHA-256 (если Release уже создан вручную, загрузите файлы из Actions вручную). Workflow создаёт Release только для push тега; сборка ветки имеет версию `v0.0.0-preview` и может обновиться до опубликованного Release.

Версионный клиент проверяет latest Release при запуске и каждый час. Новая версия устанавливается только после подтверждения: загрузка setup.exe, проверка checksums.txt и запуск установщика. Закройте клиент/локальную вкладку при обновлении, затем перезапустите. Сервер перед заменой его EXE остановите вручную. База хранится вне каталога установки и не удаляется. Установщик пока не подписан Authenticode (Windows SmartScreen может показать предупреждение). SHA-256 проверяет целостность, но не заменяет цифровую подпись; доверие основано на HTTPS и доступе к репозиторию. Приватные Releases без токена не поддержаны.

## Разработка
Go 1.23+: `go mod download`, `go test -race ./...`, `go run ./cmd/server`, `go run ./cmd/client`. Windows: `go build -o pulse-client.exe ./cmd/client`, аналогично `./cmd/server`.
